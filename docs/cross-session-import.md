# 跨会话上下文导入：可行性与建议

需求：将其他对话的部分或全部内容加入当前对话，超过上下文预算时支持压缩。已加入现有插件的第一版更新 0.1.1，无需修改 DSH 核心。本文同时保留设计依据与当前实现边界。

## 已有 DSH 基础

- `sessionQuery`：读取 live 或持久化会话，提供事件与有效 surface，读取不必恢复源会话 Agent。
- `sessionReferenceResolver`：其他会话候选列表、标题、工作目录排序和来源快照；生成持久化的 `session-reference` / `recall` 背景内容。
- `SessionReferenceSource`：包含来源会话、标签、捕获版本和事件位置、保留/省略消息数量等信息。
- 当前插件：连续选区、摘要预览与编辑、目标会话维护锁、选区冲突检查、原生事件写入和 flush。

原生引用不是任意选区导入，也没有自动执行语义摘要。它默认投影直接用户文本、助手文本与已有摘要，排除工具、推理与其他注入内容；预算不足时可能省略旧消息或缩短文本。不能把这种裁剪当作“完整导入且已经语义压缩”。

## 推荐交互

当前会话「上下文」页面新增「从其他对话导入」入口：搜索或选择来源对话，预览其有效上下文，选择连续范围或全部，显示可用预算，再选择原文导入或压缩导入，最后预览并确认加入。

“全部”默认是来源对话的当前有效上下文。原始历史应作为明确的另一种读取模式，因为它可能包含已经排除的旧内容与重复摘要；两者不能在界面里都称作“全部”。默认不递归携带来源对话已引用的其他会话。

## 预算与压缩

可用导入预算 = 当前目标模型上下文窗口 - 当前会话估算占用 - 输出预留 - 安全余量。统计须包含引用包装与来源说明的完整开销，而非只计算正文。

若能装下，保留选区原文。超过预算时先生成针对选区的摘要草稿，支持用户编辑。来源过大、连摘要请求本身都装不下时，需要分块摘要与合并摘要，并分别检查输入和输出预算。如果目标已经没有可用空间，应提示先压缩当前会话或缩小导入范围，不能静默丢弃当前上下文。

## 持久化语义

复制固定快照到目标会话；后续源会话的编辑、压缩或删除不自动改变目标。来源标签、会话 ID、捕获修订、选区和是否经过摘要应可追溯。

导入内容是历史背景，不继承源对话的系统权限、工具执行许可或历史任务指令；当前会话的要求仍然有效。源会话不被修改。确认前不改变目标有效上下文，确认时重新测量目标预算，并在目标的维护操作中写入、保存。

## 实现与验证

已覆盖源会话只读查询与精确选区、完整导入预算、跨会话来源字段的 V4 原生持久化兼容性、来源修改/删除后的草稿独立性、目标会话在预览期间增长后的预算冲突、超长来源分块压缩以及无插件内存回放。隔离的真实 DSH profile 验证原文导入和部分摘要导入，检查持久化文件、重启恢复与后续实际模型请求，见 `runtime-import-result.json`。

当前只提供有效对话文本模式，不提供原始完整历史模式。来源快照默认最多 8 MiB；分块压缩最多调用模型 64 次、共享 120 秒摘要时限。窗口容量未知或剩余空间不足时明确拒绝，不裁剪原文冒充完整导入。Token 估算与真实摘要质量仍需结合用户配置的提供方观察。
